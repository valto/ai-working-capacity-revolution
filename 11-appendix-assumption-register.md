# Assumption Register — Appendix (Release Asset #13)
### Companion to *"Why Are They Spending Trillions on AI?"* (Valto Loikkanen, CC BY 4.0)

**What this appendix is.** Every cost-curve, per-token, per-hour, per-member, and per-rack figure in this paper's five scenario workbooks — Release Asset #7 (Global Baseline), #8 (Localized EUR/Finland), #9 (AI Working-Capacity Conversion), #10 (Token-Factory Scenarios), and #11 (Humanoid Working-Capacity) — rests on a small set of visible, editable inputs. This appendix pulls every one of those inputs into a single table so a reader can see, in one place, every lever they could change and re-run the model with their own number. (Release Asset #12, the Investment-Thesis Notes, is not a separate source of new assumptions — it explicitly cites Asset #7's figures rather than re-deriving them, so it is covered here by reference, not with duplicate rows.)

**What this appendix is not.** It is not a ranking of which assumption is "right," not a forecast, and not investment, legal, tax, procurement, or policy advice. Every row below is labelled **SCENARIO ASSUMPTION** per the paper's five-class evidence standard — a visible, editable parameter used to explore a possible case, not a market figure — even in the handful of rows (marked ⚠ below) where the underlying workbook flags the number as a stand-in for missing public data rather than a deliberate "what-if" choice. Both kinds are assumptions in the sense that matters here: change the number, change every downstream result.

### Evidence-class legend (for cross-reference; only SCENARIO ASSUMPTION rows appear in this appendix)

| Code | Meaning |
|---|---|
| OBSERVED FACT | Primary documentation/official spec or pricing, independently checked against a live/primary source on or immediately before 2026-08-12. |
| ATTRIBUTED STATEMENT | A named person/org's on-record claim; not independently proven merely because it was said. |
| DERIVED CALCULATION | Transparent arithmetic from cited OBSERVED/ATTRIBUTED inputs; formula always shown. |
| **SCENARIO ASSUMPTION** | A visible, editable parameter, not a market figure. **Every row in this register.** |
| INTERPRETATION | A labelled explanation of how the above may connect; never presented as fact. |

## How to use this table

1. Find the assumption you want to change (by category or by which workbook/tier it feeds).
2. Look up its current value and the formula context in the cited workbook section.
3. Re-run that workbook's formula (every formula is shown explicitly, never just a result) with your own number.
4. Where a "suggested range to test" is given, it is drawn either from a sensitivity table the source workbook already built, or from the workbook's own stated real-world range (e.g., "$0.03–$0.40/kWh exist across real global markets" — Asset #7's own framing) — it is not a prediction of where the true value lies.

⚠ = the source workbook explicitly flags this number as a placeholder standing in for a public price/spec that could not be found (Professional-tier hardware, hyperscale rack capex, and the illustrative humanoid robot price), not a deliberate policy-style "what if" — treat these with lower confidence than the other rows, and replace with a real quote before using this tier for anything beyond illustration.

## Cross-workbook consistency notes (INTERPRETATION)

- **Most consistent lever: financing rate.** 8% APR is used, unchanged, across every tier, every workbook, and both currencies (rows 2). This is the one input a reader can compare "apples to apples" across the whole paper without adjustment.
- **Least consistent lever: electricity price.** Nine different electricity-price values are in active use across the five workbooks (rows 4–12). This remains true of the DGX Spark cooperative figures specifically (rows 5 and 6, both describing that same hardware tier) — a reader comparing those two should still reconcile them before treating the outputs as directly comparable. It is **not** related to the separate, now-resolved DGX-Station-vs-DGX-Spark tier question below.
- **CORRECTED (2026-08-13) — the former "€42-vs-€19.50–25/member/month cooperative discrepancy" is resolved, not merely narrowed.** It was never a single measurement disagreement to attribute to admin, utilization, or electricity assumptions. €42/member/month (50 members) and €21/member/month (100 members) are **[CALC]** outputs of an illustrative €100,000 DGX-Station-class capital base (row 6a) — a real hardware category NVIDIA sells but does not publish a price for — while €19.50–25/member/month describes a completely different, cheaper hardware tier (10× DGX Spark units at the verified $4,699 each). See the Token-Factory Scenario Workbook (#10) §1a/§1b and the Localized Scenario Workbook (#8) §6 for the full corrected treatment. Rows 14–15 (utilization) and row 19 (admin/overhead) remain genuine, separate levers *within* the DGX Spark tier — they no longer need to explain a cross-tier gap that turned out not to exist.
- **The FX-rate near-miss (row 27)** is a minor but real inconsistency: three workbooks each picked their own EUR/USD rate independently rather than sharing one dated, live-checked figure. The values are close enough (within ~1%) that it does not materially change any conclusion, but it is exactly the kind of silent drift this register exists to surface.
- **The five ⚠-flagged rows (23, 24, 25, 26, 6a)** are qualitatively different from the rest of this table: they are not "what if we tried a different scenario" levers but placeholders for numbers that simply could not be found as an official price in any primary source as of the 2026-08-13 cut-off (no public HGX B300 price or power spec; no official NVIDIA rack price; no official NVIDIA DGX Station price, confirmed directly on NVIDIA's own product page; no confirmed market price for the illustrative €25,000 robot). Any reader planning to act on the Professional, Hyperscale, or DGX-Station-class cooperative tiers, or on a specific humanoid-robot cost claim, should treat these five rows as the highest-priority items to replace with a real quote before relying on the workbook's output.
